# Usability test แผนที่ (รอบ 1) — แผนการทดสอบ + script

**วันที่:** 2026-10-29 · **ที่มา:** [design review §9](../design-review/2026-10-28-ui-ux-review.md) (และ §12 ขั้น B) · **คู่กับ:** [แผน telemetry](../superpowers/plans/2026-10-29-research-usability-telemetry.md)
**สถานะ:** แผน ยังไม่ได้ทดสอบ (ยังไม่มีข้อมูลให้สังเคราะห์)

## 1. ทำไมต้องทดสอบ และจะใช้ผลตัดสินอะไร

| คำถาม (§9) | ผลที่ได้ไปใช้ตัดสิน |
|---|---|
| 1. ผู้ใช้เข้าใจ**ลำดับของวัน**จากแผนที่อย่างเดียวได้ไหม | ต้องทำเส้นเชื่อมจุด (MAP-03) และหมุดแบบใหม่ (MAP-02) เร่งกว่านี้ไหม |
| 2. เพิ่มที่ใหม่ "**ระหว่างทาง**" ได้เร็วแค่ไหน | ระยะห่างในผลค้นหา (M5) / แตะ POI เพื่อเพิ่ม (TP-0077) ช่วยได้จริงไหม และการแทรกระหว่างจุดยากไหม |
| 3. บน**มือถือระหว่างทริป**ใช้อะไรมากที่สุด | **ขั้น B ของ §12** ถ้าคนสลับ List↔Map บ่อย (> 2 ครั้งต่อ session) ให้เปลี่ยนเป็น bottom sheet เต็มรูปแบบ |

ทดสอบรอบนี้**ก่อน Phase 2** (ตาม roadmap §10 `p2r`) แล้วทดสอบซ้ำด้วย script เดิมหลัง Phase 1 และหลัง Phase 2 เพื่อเทียบกัน

## 2. ผู้เข้าร่วม

- **5 คน** เป็นคนไทยที่เคยวางทริปญี่ปุ่นเองในช่วง 2 ปีที่ผ่านมา
- แบ่งเป็นทำบน**มือถือ 3 คน**และ **desktop 2 คน** ส่วนงาน C ทุกคนทำบนมือถือ
- **ไม่รับ**คนที่เคยใช้แอปนี้หรือเป็นนักพัฒนา/ดีไซเนอร์
- คำถามคัดเลือก (screener):
  1. ครั้งล่าสุดที่วางทริปต่างประเทศเองคือเมื่อไร และไปที่ไหน
  2. ตอนวางแผนใช้อะไรบ้าง (Google Maps, Excel/Sheets, Notion, Wanderlog, …)
  3. ระหว่างทริปเปิดแผนบนมือถือบ่อยแค่ไหน
- ค่าตอบแทน: ตามที่เจ้าของโปรเจกต์กำหนด
- รหัสผู้เข้าร่วม `P1`–`P5` ใช้ในบันทึกและ telemetry ห้ามใช้ชื่อจริง

## 3. การเตรียม

| อย่าง | รายละเอียด |
|---|---|
| บัญชี | แอปเป็น invite-only เจ้าของทริปต้องเชิญผู้เข้าร่วมแต่ละคนเป็น **Editor** ในสำเนาของทริปทดสอบ (คนละสำเนาต่อคน เพื่อไม่ให้การเพิ่มของคนก่อนหน้าค้างอยู่) |
| ทริป | สำเนาของ "Mount Fuji & Kamakura" (5 วัน) เช็คก่อนว่า**วันที่ 2 มีอย่างน้อย 3 จุด** และมีวันที่มีจุดในโตเกียวใกล้ Tokyo Tower ถ้าไม่มี ให้ปรับชื่อสถานที่ในงาน B ให้ตรงกับทริป |
| ลิงก์ | ส่งลิงก์ทริปที่ต่อท้ายด้วย `?ut=P1` (… `P5`) แอปจะติดรหัสนี้ไว้กับ event ของ session นั้น (ดูแผน telemetry) · **ให้ผู้เข้าร่วม sign in ในเบราว์เซอร์/มือถือที่จะใช้ให้เสร็จก่อนเปิดลิงก์นี้** ถ้ายังไม่ได้ sign in แอปจะพาไปหน้า sign-in แล้ว `?ut=` จะหายไป (event จะไม่ติดรหัส) งาน C ที่สลับไปมือถือก็ต้อง sign in บนมือถือก่อนเช่นกัน |
| โหมดแผนที่ | ทดสอบบน production (`MAPS_PROVIDER=google`) ถ้าแผนที่ขึ้นเป็นโหมดสำรอง (MapLibre) ให้จดไว้ เพราะ event `map_degraded` ก็จะบันทึกด้วย |
| ภาษา | ตอนนี้แอปยังเป็นภาษาอังกฤษ (`getLang()` ล็อค `en` ไว้จนกว่าแผน i18n Phase 6 จะเสร็จ) ให้จดว่าเป็นปัจจัยรบกวน ถ้ารอบถัดไปมีภาษาไทยแล้วให้ทดสอบเป็นไทย |
| เครื่องมือ | Google Meet หรือ LINE call ที่แชร์จอได้ และบันทึกจอ (ต้องได้ความยินยอมก่อน) · มือถือใช้การแชร์จอของ Meet app |
| ทีม | ผู้ดำเนินการ (moderator) 1 คน และผู้จด (note-taker) 1 คนถ้ามี |

## 4. งาน

กติกาทุกงาน: ให้คิดออกเสียง (think-aloud) ผู้ดำเนินการไม่ช่วยจนกว่าจะถึงเวลาจำกัด หรือผู้เข้าร่วมบอกว่าจะยอมแพ้

| งาน | คำสั่ง (อ่านให้ฟังตามนี้) | อุปกรณ์ | จำกัดเวลา | สำเร็จเมื่อ |
|---|---|---|---|---|
| **A** ลำดับวัน | "ช่วยดู**จากแผนที่อย่างเดียว** แล้วบอกว่าวันที่ 2 ไปที่ไหนก่อน แล้วไปไหนต่อ จนจบวัน" | ตามกลุ่ม (desktop: ขอให้ไม่อ่านรายการด้านซ้าย / มือถือ: กด Map ก่อนเริ่ม) | 3 นาที | บอกลำดับได้ถูกทุกจุด · **ผ่านแบบมีช่วย** = ผิด 1 จุดหรือต้องเปิดดูรายการ |
| **B** เพิ่มระหว่างทาง | "อยากกินราเมงแถว Tokyo Tower ช่วยหาร้าน แล้วใส่ไว้**ระหว่างจุดที่ 2 กับจุดที่ 3** ของวันนั้น" | ตามกลุ่ม | 5 นาที | มีร้านราเมงอยู่ในวันที่ถูกต้อง ที่ตำแหน่งระหว่างจุดที่ 2 กับ 3 · **ผ่านแบบมีช่วย** = เพิ่มได้แต่อยู่ผิดตำแหน่ง |
| **C** นำทาง | "สมมติว่าตอนนี้อยู่ที่จุดที่ 2 ของวันที่ 3 ช่วย**นำทางไปจุดถัดไป**" | มือถือทุกคน | 3 นาที | เปิด Google Maps แบบนำทาง/เส้นทางไปจุดที่ 3 ได้ (ไม่ใช่แค่หน้าข้อมูลสถานที่) |

หลังจบแต่ละงานให้ถาม **SEQ** (Single Ease Question):

> "โดยรวมแล้ว งานนี้**ยากหรือง่าย**แค่ไหน ให้คะแนน 1 ถึง 7 โดย 1 คือยากมาก และ 7 คือง่ายมาก"

## 7. วัดผลและสรุป

- **อัตราสำเร็จ** ต่องาน (นับ "มีช่วย" เป็นครึ่ง) · **เวลา** ใช้ median · **SEQ** ใช้ค่าเฉลี่ย (ค่าอ้างอิงทั่วไปประมาณ 5.5 ถ้าต่ำกว่านั้นถือว่ายากกว่าค่าเฉลี่ย)
- 5 คนพอสำหรับหาปัญหาที่เจอบ่อย **ไม่พอ**สำหรับสถิติ ให้รายงานเป็นตัวเลขดิบ เช่น "3/5"
- จัดกลุ่มปัญหาตาม §2.2 (M1–M15) ถ้าเจอปัญหาใหม่ให้ตั้งรหัส `U1…`
- ขั้น B ของ §12: ดูจากทั้งการสังเกตและ telemetry 2–3 สัปดาห์ (query ด้านล่าง)

### Query (Neon SQL editor, ตาราง `ui_event` จากแผน telemetry)

```sql
-- ผลของ usability test: event ต่อผู้เข้าร่วม
select ut, name, count(*) from ui_event
where ut is not null group by 1, 2 order by 1, 2;

-- §12 ขั้น B: สัดส่วน session บนมือถือที่สลับ List↔Map มากกว่า 2 ครั้ง (ไม่นับ session ทดสอบ)
-- ตัวหาร = ทุก session ที่เปิดทริป (event trip_view) แม้ไม่ได้แตะแผนที่เลย
-- toggles = นับทั้งสองทิศ (List→Map และ Map→List) · to_map = นับเฉพาะครั้งที่สลับไป Map
-- (เกณฑ์ "> 2 ครั้ง" ของ §12 ต้องเลือกว่าใช้ตัวไหน ดูหมายเหตุด้านล่าง)
with s as (
  select sid,
         count(*) filter (where name = 'fullmap_toggle') as toggles,
         count(*) filter (where name = 'fullmap_toggle' and props->>'on' = 'true') as to_map
  from ui_event
  where ut is null and props->>'vp' = 'mobile' and created_at > now() - interval '21 days'
  group by sid
  having count(*) filter (where name = 'trip_view') > 0
)
select count(*) filter (where toggles > 2)::float / nullif(count(*), 0) as share_over_2,
       count(*) filter (where to_map > 2)::float / nullif(count(*), 0) as share_to_map_over_2,
       percentile_cont(0.5) within group (order by toggles) as median_toggles,
       count(*) as sessions
from s;

-- หมายเหตุ: session = แท็บเดียวกันที่ไม่ได้ว่างเกิน 30 นาที (แผน telemetry) ไม่ใช่ทั้งชีวิตของแท็บ
-- ฟีเจอร์ไหนถูกใช้ (มือถือ vs desktop)
select name, props->>'vp' as vp, count(*) from ui_event
where created_at > now() - interval '21 days' group by 1, 2 order by 3 desc;
```

## 8. ความเป็นส่วนตัว

- บันทึกจอเก็บใน Google Drive ของเจ้าของโปรเจกต์ แชร์ภายในทีมเท่านั้น และ**ลบภายใน 90 วัน**
- ในบันทึกใช้แค่รหัส `P1`–`P5` เก็บรายชื่อจริงแยกไว้คนละไฟล์
- telemetry ไม่เก็บชื่อสถานที่, place id, trip id, user id, อีเมล หรือพิกัด (ดูแผน telemetry)
