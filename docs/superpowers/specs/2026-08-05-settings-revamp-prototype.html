What this proposes

  • Scope decides the route, not a section header. Trip things live at /trip/[id]/settings: details · budget & currency · people · integrations · delete. Account things live at /settings: preferences · API tokens. Nothing appears in both places, so there is never a question of which copy is authoritative.
  • Three toggles are cut, not redesigned. notifEmail, notifPush and publicTrip are written to the DB today and read by nothing — no mailer, no push, no public view. Shipping them into a new design would sell three features that do not exist. They come back when something consumes them. units stays because TP-0016 makes it real.
  • The settings modal is deleted. One component serves both routes; only the section list differs. Two surfaces meant two state paths, two save paths, and a standing question about where each new setting belongs — for a screen nobody visits mid-task. The header icon links to /settings instead of opening a dialog.
  • Blocked saves explain the blockage. The date-shrink guard names how many days are in the way and what to do, rather than rejecting the form.
  • Currency change states its consequence. Amounts are never converted; the notice counts the entries that would be stranded and offers the relabel that already exists.
  • Not-yet-shipped is stamped, not greyed. Theme and language read as deliberately deferred with a reason, instead of looking broken.
  • Deferred: account-level default currency for new trips; a per-trip archive action.
