# แผ่นช่วงเดินทาง (Leg detail sheet): ดูและแก้รายละเอียดการเดินทางระหว่างจุด

วันที่: 2026-11-05 · สถานะ: ผู้ใช้อนุมัติหน้าตาแล้ว (ดูหน้าตัวอย่างผ่าน visual companion) · ยังไม่เปิดการ์ด — ต้องผ่าน /scrutinize ก่อน

## 1. ที่มาและเหตุผล

ผู้ใช้วางแผนทริปเป็น "จุดตามวัน" และการเดินทางส่วนใหญ่คือจากจุดหนึ่งไปอีกจุดหนึ่งในวันเดียวกัน (เช่น นั่ง rapi:t จาก Namba ไปสนามบินคันไซ) สิ่งที่ผู้ใช้ต้องการ (คำของผู้ใช้):

- ใส่รายละเอียดของ **การเดินทางนั้น** (ไม่ใช่ของจุด) เช่น ชานชาลา ราคาตั๋ว ที่ซื้อตั๋ว
- กดดูโน้ตหรือรายละเอียดได้ทั้งตอนนำทางในโหมดแผนที่ และในหน้ารายการจุดของวัน
- แก้เองบนหน้าเว็บได้ ไม่ใช่ให้ผู้ช่วย AI ใส่อย่างเดียว
- ต้นทางและปลายทางของการเดินทางคือจุดที่มีอยู่จริงในวันนั้น เส้นบนแผนที่จึงถูก

ปัญหาที่เจอ: เมื่อสั่งผู้ช่วย AI สร้างทริป มันสร้าง "จุดปลอม" ที่ตั้งชื่อเป็นการเดินทาง (`kind:"transit"` ไม่มีพิกัด) เพื่อจะมีที่ใส่โน้ต ทำให้ช่วงนั้นไม่มีต้นทาง/ปลายทางจริงบนแผนที่

### สิ่งที่มีอยู่แล้ว (ตรวจในโค้ด main `88f0e31`)

- **ข้อมูล:** TP-0141 เพิ่ม `segment.note` / `segment.duration_min` และขาเช้าจากโรงแรม `day.start_mode` / `start_duration_min` / `start_note` (`app/src/db/schema.ts`)
- **API:** ผู้ช่วยใส่ได้ผ่าน `arrive` ตอน import และ `PUT/DELETE /places/:placeId/arrive` (SKILL.md บรรทัด ~189 และ ~346) และ SKILL.md ห้ามสร้างจุดปลอมแล้ว (มี warning `transit_as_place`)
- **หน้าเว็บ:** แถบระหว่างจุด (`app/src/components/segment.tsx`) แสดงโน้ตแบบอ่านอย่างเดียว (กดขยาย) และเปลี่ยนวิธีเดินทางได้ด้วย `SegmentModePicker` เท่านั้น **ไม่มีที่แก้โน้ตหรือเวลา**
- **โหมดแผนที่:** ไม่แสดงโน้ตของช่วงเลย กดเส้น/ป้ายกลางเส้นแล้วเลือกจุดปลายทาง (TP-0136, `onLegSelect`)

ดังนั้นงานนี้คือ **หน้าเว็บ** เป็นหลัก ข้อมูลใน DB และ API มีครบแล้ว แต่ **ข้อมูลที่ส่งให้แผนที่และแถบในรายการไม่พอ** ต้องขยาย (ดู §7 ข้อ 1, 4)

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / ห้ามเกิด

**เป้าหมาย**
1. มี "แผ่นช่วงเดินทาง" ตัวเดียว ใช้ทั้งในหน้ารายการและโหมดแผนที่ ดูและแก้ วิธีเดินทาง · เวลาเดินทางโดยประมาณ · โน้ต ได้ และมีปุ่มนำทาง
2. หน้ารายการ (ผู้ใช้เลือกแบบ A): แถบระหว่างจุดเหลือบรรทัดเดียว — วิธีเดินทาง · เวลา · ไอคอนโน้ต (ถ้ามีโน้ต) · ปุ่มนำทาง กดแถบ (ไม่ใช่ปุ่มนำทาง) แล้วเปิดแผ่น
3. โหมดแผนที่ (ผู้ใช้เลือกแบบ B): กดเส้นทางหรือป้ายกลางเส้น แล้วแผ่นเลื่อนขึ้นจากด้านล่าง
4. คนที่ดูได้อย่างเดียวเห็นแผ่นเดียวกันแบบอ่านอย่างเดียว (ซ่อนช่องแก้และปุ่มบันทึก)

**ไม่ใช่เป้าหมาย (รอบนี้)**
- แปลงจุดปลอมในทริปเก่าให้เป็นโน้ตของช่วง (ผู้ใช้: ไม่ต้องทำ)
- เปลี่ยน schema (ไม่มี) · API ใช้ของเดิม เพิ่มแค่เอกสารของ `arrivalMode`/`departureMode`
- การเดินทางแบบจอง (`transport_booking`, เที่ยวบิน/รถไฟข้ามเมือง) — เป็นอีกเรื่อง (TP-0142 ทำเรื่องแผนที่ไปแล้ว)
- ดึงเวลาเดินทางจาก Google Routes (ยังคงไม่ใช้ Routes API)

**ห้ามเกิด (ถึงทำงานได้ก็ถือว่าล้มเหลว)**
- ต้องรู้ว่าต้องไปหน้าอื่นถึงจะแก้โน้ตของช่วงได้
- แก้แล้วปิดแผ่นแล้วการแก้หายเงียบ ๆ
- แผ่นบังจนนำทางไม่ได้ หรือกดเส้นบนแผนที่แล้วไม่ได้เลือกจุดปลายทางเหมือนเดิม
- หน้าตาไม่เข้ากับส่วนอื่นของแอป (ผู้ใช้สั่งให้ใช้ design token และรูปแบบ component ที่มีอยู่)

## 3. หน้าตาที่ผู้ใช้อนุมัติ

### 3.1 แถบระหว่างจุดในหน้ารายการ
- บรรทัดเดียว: ไอคอน+ชื่อวิธีเดินทาง · เวลา (`durationMin` แบบ "≈" ก่อน ถ้าไม่มีใช้ `time` ข้อความเก่า — กลับลำดับจากปัจจุบัน ดู §5) · ไอคอนโน้ต · ปุ่ม "นำทาง" ชิดขวา
- สีแถบซ้ายและสีไอคอนวิธีเดินทางตามสีของช่วง (`--leg-N` ผ่าน `legStyle(slot)` ตามที่ใช้อยู่)
- ไอคอนโน้ตใช้ชุดสีโน้ตเหลือง (`--note-soft` / `--note-fg` / `--note-border`) แบบเดียวกับโน้ตของจุด แสดงเฉพาะเมื่อมีโน้ต
- ทั้งแถบ (ยกเว้นปุ่มนำทาง) เป็นปุ่มเปิดแผ่น ขนาดกดได้อย่างน้อย 44px
- `SegmentModePicker` แบบในแถบ **ย้ายเข้าไปอยู่ในแผ่น** (เปลี่ยนวิธีเดินทางต้องกด 2 ครั้งแทน 1) — ผลตรงจากที่ผู้ใช้เลือกแบบ A แถบบรรทัดเดียว

### 3.2 แผ่นช่วงเดินทาง
- ใช้ `Modal` (`app/src/components/ui/modal.tsx`): มือถือเป็นแผ่นจากล่าง จอ ≥768px เป็นกล่องกลางจอ ใช้ขนาดเล็ก (`panelSm`) เพราะมีฟิลด์น้อย
- หัว: "ต้นทาง → ปลายทาง" (ชื่อจุดจริงของช่วง) บรรทัดรอง: ลำดับจุดและวัน
- วิธีเดินทาง: `Segmented` (เดิน / ขับ / รถสาธารณะ — โหมดเดิมของ `segmentModeEnum`)
- เวลาเดินทางโดยประมาณ (นาที) → `durationMin` / `start_duration_min`
- โน้ตการเดินทาง: textarea → `note` / `start_note`
- ปุ่ม: "นำทาง" (ลิงก์ Google Maps แบบเดิม `gmapsDirectionsUrl`) และ "บันทึก" (`Button` หลัก)
- แก้แล้วกดปิด/Esc/scrim → ถามก่อนทิ้งด้วย `ConfirmDialog` แบบเดียวกับ `place-note-modal.tsx` (ใช้ไฟล์นี้เป็นต้นแบบ)
- อ่านอย่างเดียว: แสดงวิธีเดินทาง เวลา โน้ตเป็นข้อความ และปุ่มนำทาง

### 3.3 โหมดแผนที่
- กดเส้นหรือป้ายกลางเส้น: ทำเหมือนเดิม (เลือกจุดปลายทาง) **และ** เปิดแผ่นของช่วงนั้น
- ใช้ทั้ง renderer ของ Google และ MapLibre (ผ่าน `onLegSelect` ที่มีอยู่)
- ปุ่มนำทางบน connector ระหว่างการ์ดในแถบการ์ดมือถือ (TP-0130) ทำงานเหมือนเดิม

## 5. ตัดสินโดยผู้ออกแบบ (ผู้ใช้ตรวจได้)

- **ขาแต่ละชนิด:** `dayLegs` (`day-augment.ts:127`) ให้ผล 5 แบบ — `segment` (มี note/duration), `start` (ขาเช้าจากโรงแรมสุดท้ายที่เริ่มวัน → จุดแรก มี `start_note`/`start_duration_min`, เกิดเฉพาะเมื่อวันนั้นมีจุด), `hotel departure` (โรงแรมซ้อน **และ** ขาเดียวของวันที่ไม่มีจุดเลย), `hotel arrival` (ขาสุดท้ายเข้าโรงแรม มีแค่ mode), และ `null` (ช่องระหว่างจุดที่ยังไม่มีแถว segment) ทุกแบบเปิดแผ่นได้ `null` เปิดเป็นแผ่นแบบ segment ที่แก้ได้ ค่าเริ่มต้นวิธีเดินทาง `day.defaultMode ?? 'drive'` และบันทึกแล้วสร้างแถวให้ (`writeArrive` ทำอยู่แล้ว) ชนิดที่ไม่มีที่เก็บโน้ต/เวลาแสดงแผ่นที่มีแค่วิธีเดินทางกับปุ่มนำทาง (ผู้ใช้เลือก (ก), §6)
- **ล้างค่า:** ลบโน้ตจนว่างแล้วบันทึก = ล้างโน้ต (เก็บเป็น null) เวลาเว้นว่าง = null
- **เวลาที่แสดงบนแถบ:** `segment.time` เป็นข้อความเก่า (แถวใหม่เก็บ `''`, มีค่าแค่ข้อมูล seed) แผ่นแก้เฉพาะ `durationMin` และเมื่อ `durationMin` มีค่า แถบแสดงค่านี้ก่อน `time` (กลับลำดับจากเดิมที่ `time` ชนะ) เพื่อให้แก้แล้วเห็นผลบนแถบทันที
- **บันทึกตามชนิดขา (กฎเดียว):** `segment` / `start` / `null` → เรียก `setPlaceArrive(userId, toPlaceId, { mode, durationMin, note }, { expectFromId })` **ครั้งเดียว** (mode, เวลา, โน้ต ไปด้วยกันใน transaction ที่ lock วันแล้ว ห้ามแยกเรียก `setSegmentMode`) แปลง input ด้วย `parseArrive` ให้ขีดจำกัดตรงกับ API · ขาโรงแรม → `setHotelLegMode` เดิม (mode อย่างเดียว) ตัวเลือกวิธีเดินทางมี 3 แบบเหมือน `SegmentModePicker` ปัจจุบัน (ไม่มี "ตามค่าเริ่มต้นของวัน" ในแผ่น)
- **แผ่นค้างระหว่างที่แผนเปลี่ยน:** แผ่นอ้างช่วงด้วย (วัน, จุดต้นทาง, จุดปลายทาง) ตอนบันทึก server ตรวจว่าสองจุดนี้ยังติดกันในวันนั้น ถ้าไม่ใช่ ตอบ error และแผ่นแสดง "แผนของวันนี้เปลี่ยนไปแล้ว ปิดแล้วเปิดใหม่" โดยไม่ปิดแผ่นและไม่ทิ้งข้อความที่พิมพ์ (ไม่เขียนทับช่วงผิด)
- **แผนที่กับขาที่เกี่ยวกับโรงแรม:** โรงแรมเป็น pin ของวันอยู่แล้ว กดเส้นจึงเลือกจุดปลายทางได้ทุกชนิด (รวมโรงแรม) หัวแผ่นใช้ชื่อโรงแรมเป็นต้นทาง/ปลายทาง ปิดแผ่นแล้วจุดที่เลือกยังคงถูกเลือกอยู่ (เหมือนกดเส้นในปัจจุบัน)
- **จอใหญ่:** ไม่มีหน้าตาแยก ใช้ `Modal` ที่เป็นกล่องกลางจออยู่แล้ว
- **ข้อจำกัดของโน้ต:** ใช้ความยาวสูงสุดเดียวกับที่ API รับ (ผู้สร้างตรวจค่าจาก `parseArrive`)

## 6. คำตอบของผู้ใช้ (2026-11-05)

1. **เปลี่ยนวิธีเดินทางต้องกด 2 ครั้ง (ผ่านแผ่น): รับได้** และ **ต้องรองรับ API/MCP ด้วย** → ดู §6.1
2. **ขาสุดท้ายเข้าโรงแรม: ทางเลือก (ก)** แผ่นของขานี้มีแค่วิธีเดินทางกับปุ่มนำทาง ไม่เปลี่ยน schema รอบนี้
3. **จุดปลอมในทริปเก่า: ไม่ต้องทำ** ผู้ใช้จัดการเอง ไม่เปิดงานแยก

### 6.1 ทำได้เท่ากันทั้งหน้าเว็บ, API และ MCP (ข้อบังคับ)

ทุกอย่างที่แผ่นแก้ได้ ต้องทำได้ผ่าน REST API ด้วย service ตัวเดียวกัน (MCP ของ TP-0035 จะห่อ API นี้ จึงได้ตามไปโดยอัตโนมัติ):

| ในแผ่น | ชนิดขา | REST ที่มีอยู่ | งานรอบนี้ |
|---|---|---|---|
| วิธีเดินทาง + เวลา + โน้ต | `segment` (เข้าจุด i>0) | `PUT /places/:placeId/arrive` (`leg-service.ts` `writeArrive`/`applyPlaceArrive`) | server action ของแผ่นต้องเรียก service ตัวเดียวกันนี้ ห้ามเขียนแยก |
| วิธีเดินทาง + เวลา + โน้ต | `start` (เช้าจากโรงแรม → จุดแรก) | `PUT /places/:firstPlaceId/arrive` | เหมือนข้างบน |
| วิธีเดินทาง | ขาโรงแรม `arrival`/`departure` | `PATCH /hotels/:id` รับ `arrivalMode`/`departureMode` (`HOTEL_FIELDS`) แต่ **ไม่ validate** (ค่าผิดน่าจะได้ 500) และยังไม่มีในเอกสาร | เพิ่ม validate enum ใน `patchHotel` + test (ค่าผิด → 400) แล้วค่อยเขียนใน API.md และ SKILL.md · service คนละตัวกับแผ่น (`updateHotel` vs `setHotelLegMode`) แต่ผลลัพธ์ในคอลัมน์เดียวกัน |
| ล้างโน้ต/เวลา | `segment`/`start` | `PUT …/arrive` ด้วย `durationMin:null, note:null` (DELETE บนจุดแรกล้าง `start_mode` ด้วย จึงห้ามใช้จากแผ่น) | แผ่นไม่ส่ง DELETE หรือ `null` ทั้งก้อน |

- การตรวจ "แผ่นค้าง" (§5) ทำในฝั่ง action ของหน้าเว็บ API อ้างช่วงด้วย placeId ของจุดปลายทางอยู่แล้ว จึงไม่มีปัญหาเรื่องตำแหน่ง
- กฎแสดงเวลา (§5: `durationMin` ชนะ `time`) เป็นเรื่องการแสดงผลใน `segment.tsx` เท่านั้น API ส่งค่าดิบ (`time`, `durationMin`) เหมือนเดิม
- test: มี test ระดับ service ที่ยืนยันว่า action ของแผ่นกับ route ของ API ได้ผลลัพธ์เดียวกันสำหรับข้อมูลชุดเดียวกัน

1. **ข้อมูลของแผนที่ (B1):** ขยาย `MapLeg` ใน `buildMapLegs` จาก `dayLegs` ให้มีตัวระบุช่วง `{ kind, fromId, toId, hotelId?, hotelLeg?, note, durationMin }` และเปลี่ยน `onLegSelect` ให้ส่งตัวระบุนี้ (ไม่ใช่แค่ `toId`) ตัวเปิดแผ่น (provider + host) อยู่ใน trip layout เพราะแผนที่อยู่ใน `layout.tsx` และรายการอยู่ใน `page.tsx` สิทธิ์แก้ใช้ `canWrite(role)` ของ layout ป้าย `map_leg_go` เปลี่ยนเป็นข้อความที่บอกว่าเปิดรายละเอียด
2. **ขาเช้า (M2, แก้ตามรอบ 2):** ไม่มี flag พิเศษ บันทึกจากแผ่นเขียน `start_mode` เป็นค่าที่แสดงอยู่เสมอ (เหมือน API) ยอมรับผลข้างเคียง: หลังบันทึก วันนั้นไม่ตาม `hotel.departureMode` อีก ซึ่งตรงกับสิ่งที่ API/MCP เห็น (`start`/`arrive` ไม่เป็น null) ล้างโน้ต/เวลาใช้ PUT ที่ส่ง `null` เฉพาะสองช่องนั้น
3. **แผ่นค้าง (M3):** `setPlaceArrive` รับ precondition ใหม่ (optional) แบบ `{ at: 'start' } | { after: placeId }` ตรวจใน transaction ที่ lock วัน: `{after}` → `order[pos-1] === after`; `{at:'start'}` → จุดปลายทางยังเป็นจุดแรก (`pos === 0`); จุดปลายทางถูกลบไปแล้วก็นับเป็น "แผนเปลี่ยน"; ขาโรงแรมไม่มีการตรวจ (mode อย่างเดียว) ไม่ผ่าน → service โยน `ServiceError('conflict', 'leg_changed')` แล้ว action แปลงเป็น `ActionResult` ที่แผ่นแสดง "แผนของวันนี้เปลี่ยนไปแล้ว…" ข้อความที่พิมพ์ไม่หาย · API ไม่ส่ง precondition (พฤติกรรม API เดิมไม่เปลี่ยน) · ระหว่างรายการกำลังย้ายจุด (`pendingMoveId != null`) ปิดการเปิดแผ่นชั่วคราว
4. **รายการ (M4):** `AugmentedSeg` (`page.tsx:154`) ต้องพกตัวระบุช่วงเดียวกับข้อ 1 · `StaticItem` (คนดูอย่างเดียว และก่อน hydrate) เปิดแผ่นได้เพราะตัวระบุช่วงมากับ prop ของ segment แล้ว แผ่นเป็นแบบอ่านอย่างเดียวเมื่อ `!canEdit` (ก่อน hydrate ของคนที่แก้ได้: ยังเปิดไม่ได้จนกว่า hydrate เสร็จ) · ชิป "ไม่มีตำแหน่ง" กดเปิดแผ่นได้ (ซ่อนปุ่มนำทาง) และลิงก์ "แก้ตำแหน่ง" อยู่ข้าง ๆ เหมือนเดิม · แถบเป็น `<button>` คู่กับลิงก์นำทาง `<a>` (ห้ามซ้อนลิงก์ในปุ่ม)
5. **ขาโรงแรม (M6):** แผ่นของขาโรงแรมมีคำอธิบาย "ใช้กับทุกวันที่พักที่นี่" เพราะ mode เก็บที่โรงแรม
6. **e2e ที่ต้องย้าย (M5):** ใน `app/e2e/mobile-layout.spec.ts` ราว 13 test ใช้ตัวเลือกบนแถบหรือขยายโน้ตในที่ (helper `legsOf` ~l.1861; TP-0141 l.1924/1957/1982/2005; TP-0150 กรอบแตะ l.2061/2081; C0/sync l.2175/2233/2351/2382/2483/2511; map L2 l.2940) แผนต้องมีรายการว่า test ไหนเขียนใหม่ผ่านแผ่น test ไหนเลิกใช้ (ขยายในที่, เรขาคณิตกรอบแตะ) และ scenario พร้อมกันข้อไหนยังต้องคง (เช่น บันทึกระหว่างอีกวันกำลังบันทึก) และต้องนับงานนี้ในแผน
7. **ปุ่ม Back บนมือถือ (N2):** เมื่อแผ่นเปิดอยู่เหนือแผนที่เต็มจอ กด Back ต้องปิดแผ่นก่อน (ถ้าแก้ไว้ → ถามก่อนทิ้ง) ไม่ปิดแผนที่ทิ้งทั้งที่แผ่นค้าง ทำโดยให้การเปิดแผ่นบนแผนที่เต็มจอ push history entry หนึ่งอันผ่าน `lib/full-map-history.ts` (ไม่เพิ่มกลไกใหม่ข้าง ๆ) และปิดแผ่นด้วยปุ่มอื่น = pop entry นั้น ผู้สร้างออกแบบรายละเอียดให้เข้ากับ Back ของแผนที่เต็มจอที่มีอยู่ และมี e2e: Back ครั้งแรกปิดแผ่น ครั้งที่สองปิดแผนที่
8. **คีย์บอร์ด (N3):** ทางเข้าด้วยคีย์บอร์ดคือแถบในรายการ เส้นบนแผนที่ใช้นิ้ว/เมาส์อย่างเดียว (ยอมรับ)
9. **ขีดจำกัด (N5):** โน้ต ≤ `ARRIVE_NOTE_MAX` = 500 ตัวอักษรหลัง trim, เวลา 0–`ARRIVE_DURATION_MAX` = 2880 นาที (`legs.ts:3–4`) · `durationMin = 0` ไม่แสดงบนแถบ
10. **สี (N6):** ช่วงที่ไม่มีสี (`legSlot == null`) ใช้สีกลาง (`--border-strong` / `--muted`)
11. **ไฟล์ใหม่ห้ามมีสีดิบและห้าม inline style แบบ `place-note-modal.tsx`** (N7) ใช้ CSS module + token
12. **test ระดับ service/integration (N8):** ปฏิเสธคู่ที่ไม่ติดกัน · ล้างโน้ตขาเช้าแล้ว `start_mode` ยังอยู่ · mode ขาโรงแรมมีผลทุกคืน · ช่วง `null` บันทึกแล้วสร้างแถว · PATCH hotel mode ผิด → 400 · แผ่นอ่านอย่างเดียวจากทั้งรายการและแผนที่ (e2e)

ทางเลือกที่พิจารณาแล้วไม่ใช้: คงตัวเลือกบนแถบแล้วทำแค่หน้าต่างโน้ต (ถูกกว่าแต่ขัดกับที่ผู้ใช้เลือกแบบ A) · โชว์โน้ตใน connector ของแถบการ์ดแทนแผ่น (ผู้ใช้เลือกแบบ B แล้ว)

## 8. ที่เหลือให้ผู้สร้างตัดสิน

- โครง component (แยก `LegSheet` + hook เปิด/ปิด ที่ใช้ร่วมกันระหว่างรายการกับแผนที่)
- จะเขียนผ่าน server action ใหม่ตัวเดียว (`setLegAction`) หรือหลายตัวตามชนิดขา
- รายละเอียด a11y (ชื่อปุ่ม, focus กลับไปที่แถบหลังปิด) ตามแบบ `Modal` ที่มีอยู่
- e2e ที่ต้องมี: เปิดแผ่นจากรายการ แก้โน้ตแล้วเห็นไอคอนโน้ต, เปิดจากเส้นบนแผนที่ (มือถือ), อ่านอย่างเดียวไม่มีช่องแก้
