# TP-0141 Legs (`arrive`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a place carry `arrive: { mode, durationMin?, note? }` (the leg that reaches it). Store place-to-place legs on `segment` (new `note`, `duration_min`) and the hotel-to-first-stop leg on `day` (`start_mode`, `start_duration_min`, `start_note`). Make every leg visible and writable through the UI, REST and import.

**Architecture:** A pure leg model (`lib/legs.ts`) owns the pair keys, the note realignment, the derived `arrive`/`start` views and the import leg rows. A DB service (`lib/services/leg-service.ts`) wraps it inside `dbNode` transactions that start with a `FOR UPDATE` lock on the day row. `removePlace` and `reorderPlaces` move into those transactions. Rows stay where they are and `mode` stays positional; only `note`/`durationMin` follow the `(from, to)` pair. `dayLegs` gains a `start` leg kind that reads `day.start_mode` first.

**Tech Stack:** Next.js 16 App Router, Drizzle ORM 0.45 (pg), Neon Postgres (`db` = neon-http, `dbNode` = postgres-js), vitest (node), Playwright 1.64 (mobile emulation).

**Spec:** `docs/superpowers/specs/2026-11-04-aaux2-legs-and-tbd-hotels-design.md`. This plan covers §1 (TP-0141), §3 (shared contract) and the TP-0141 columns of §4–§5. TP-0143 (hotels) is a parallel plan and is not covered here.

## Review Focus

1. **A place parked at idx ≥ 1 000 000 by a partial reorder list** (a stale tab sent an incomplete `placeIds`). `arrive` writes and reads must use the place's *live position* in the day (index in `ORDER BY idx` of non-deleted places), never raw `places.idx`. Otherwise a segment lands at idx 1 000 002. Test: Task 4 `writes arrive by live position, not raw idx`.
2. **A 500-char note with no spaces on a 360 px phone** must stay on one line with an ellipsis and cause no horizontal page overflow. Tapping it expands it in place. Test: Task 10 e2e `a long leg note stays one line on a phone`.
3. **`note: "   "`, `durationMin: "90"`, `90.5`, `-1`, `2881`, `mode: "train"`, `arrive: []`** must give a whitespace note → `null` and every other value → `400` with a message naming the field. Test: Task 3 `parseArrive` cases.
4. **A viewer-role member calling `PUT`/`DELETE /places/:id/arrive`** gets 403 and nothing is written (no row, no day change). Test: Task 8 `viewer cannot write arrive`.
5. **An arrival day (day 0, no begin hotel) whose first place has `arrive`** stores `start_*`, shows no start leg in the list, and emits `arrive_without_origin` exactly once for that day. Tests: Task 5 `dayLegs with b = 0 has no start leg`, Task 9 `arrive_without_origin once per day`.

  ```ts
  export function importLegRows(placeCount: number, arrives: (ArriveInput | null)[]): { start: ArriveInput | null; segments: { idx: number; mode: SegmentMode; distance: string; time: string; note: string | null; durationMin: number | null }[] };
  ```
- Semantics:
  - `legNotesByPair`: the key for segment idx i is `pairKey(order[i], order[i+1])`. The start leg's key is `pairKey(START_KEY, order[0])`. Rows with no `to` (stale idx ≥ `order.length - 1`) are skipped.
  - `realignLegNotes`: returns one entry for **every** idx in `segIdxs`, set to `before.get(newPair) ?? {note:null,durationMin:null}`. An idx with no new pair (≥ `newOrder.length - 1`) gets nulls. `start` uses `(START_KEY, newOrder[0])`; an empty order gives nulls.
  - `dayStartView`: `null` when `startMode` is null, with no fallback.
  - `arriveForPlaces`: index 0 is `start`. Index j ≥ 1 is the segment with `idx === j-1`, or `null` when that row is missing.
  - `legDayView`: strips the three raw `start*` keys, adds `start`, and adds `arrive` to each place by array position.
  - `importLegRows`: emits `placeCount - 1` rows. Row `idx = j-1` comes from `arrives[j]`, or `{ mode: 'drive', note: null, durationMin: null }` when that is null. `distance`/`time` are `''`. `start = arrives[0] ?? null`.
