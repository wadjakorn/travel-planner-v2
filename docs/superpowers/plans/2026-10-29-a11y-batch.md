# Accessibility Batch (Operable / Understandable / Screen reader) Implementation Plan

> **Ticket:** TP-0094

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the remaining small §5 findings. Map popups get honest semantics and Esc. The List/Map toggle stops pretending to be tabs. The search box shows focus. Small controls get ≥44 px touch areas. The trip map gets a spoken summary and a labelled distance chip. Users see real copy instead of raw server errors.

**Architecture:** Each finding is a localized edit to the component that owns it. Three shared pieces are added:
- a `.tp-hit` hit-area utility in `globals.css` (coarse pointers only, `::after`-based, so the visual size stays the same);
- pure text helpers in `lib/map-a11y.ts`, unit-tested and used by both map renderers;
- `lib/action-errors.ts`, which dedupes the redirect-digest check and logs failures; every surface shows fixed copy instead of `err.message`.

**Tech Stack:** Next.js 16, React 19, Tailwind v4.2 (`pointer-coarse:` variant), `@vis.gl/react-google-maps`, `react-map-gl/maplibre`, vitest. axe-core 4.11.4 is used for the browser smoke.

**Spec:** `docs/design-review/2026-10-28-ui-ux-review.md` §5: A11, A12, A13, A14, A18; "Screen reader (แผนที่)" table (region + distance chip); A17 is conditional (see Decision 4). Also §8 chip copy (screen-reader text only here).

**Touches:** `globals.css` (new `.tp-hit` block only), `real-map-canvas-google.tsx`, `real-map-canvas-maplibre.tsx`, `map-renderer-props.ts` (one optional prop), `persistent-map.tsx` (one prop), `pin-card.tsx`, `map-preview-marker.tsx`, `map-panel-toggle.tsx`, `ui/button.tsx`, `ui/input.tsx` (conditional), `place-search-picker.tsx`/`.module.css`, `sortable-place-item.tsx`, `sortable-place-list.tsx`, `itinerary-list.module.css` (`.segment` coarse min-height only), `place-note-launcher.tsx`, `place-note-modal.tsx`, `segment.tsx`, `segment-mode-picker.tsx`, `day-mode-picker.tsx`, `trip-delete-button.tsx`, `account-menu.module.css`, `notes-view.tsx`, `bookings-view.tsx`, `app/error.tsx`, `app/trip/[id]/error.tsx`, `app/package.json` (devDep).

## Decision needed

1. **A11: pin card and preview popup use `role="group"` + `aria-label`, plus Esc to close and focus return. Not a real dialog.** (recommended)
   - A dialog must take focus on open. The card opens on every list-row activation and pin tap. Pulling focus out of the itinerary list on each row press would break keyboard list navigation.
   - Both renderers deliberately open popups without focus (`shouldFocus={false}` at `real-map-canvas-google.tsx:154,167`; `focusAfterOpen={false}` in MapLibre).
   - The card is non-modal content beside the list. A labelled group describes it honestly.
2. **A12: keep the List/Map toggle and switch it to two `aria-pressed` buttons in a labelled group.** The §3.2 bottom sheet that would delete the toggle is not built. TP-0076 shipped the carousel on top of the toggle, so the toggle stays.
3. **Axe smoke: add `axe-core@4.11.4` as a devDependency and run it through Playwright MCP in the browser task.** `@playwright/test` is not added.
   - axe-core is already in the lockfile, pulled in transitively by `eslint-plugin-jsx-a11y`. It has zero runtime deps.
   - The repo has no browser test runner (vitest `environment: 'node'`, `include: ['src/**/*.test.ts']`) and no jsdom.
   - A CI e2e runner (Playwright + browsers) is a separate, heavier decision.
4. **A17 (`Input` invalid state): only if the modal-consolidation plan doesn't already own it.** Task 7 is written to be skipped if that plan landed `aria-invalid` styling on `ui/input.tsx`. The pin-picker plan handles `aria-invalid` for its own fields in `trip-create-form.module.css`.

## Global Constraints

- **Hit areas.** Use `pointer-coarse` only, so the desktop layout doesn't change.
  - Minimum 44×44 CSS px (WCAG 2.5.5 as cited by the review).
  - Expand with `::after`. Don't change visual size except where noted.
  - Adjacent targets' expanded areas must not overlap. Where they would, widen the gap: centre-to-centre ≥ 44 px.
- **`.tp-hit` lives in `@layer components`**, so caller utilities like `absolute` still win over its `position: relative`.
- **Colours.** Tokens only. No new hex.
- **No new Google calls.** Cost impact: $0.
- **Copy (EN, exact):**
  - toggle group label `View`; buttons `List` / `Map`
  - map summary: `{dayLabel} has {n} place(s): 1. {name}, {time}; 2. …` / `{dayLabel} has no places yet.`
  - distance chip SR text `Total travel for this day: {distance}, {time}`
  - failure copy: per Task 6 table
- **Behaviour.** TP-0076 carousel (`map-stop-carousel.tsx`) and the `body[data-fullmap]` layout (`globals.css:270-300`, keyed on `data-map-toggle`/`data-map-*` attributes, not roles) must behave as before.

## Review Focus

1. **Esc on a Google `InfoWindow` pin card.** Google may also close its InfoWindow natively on Esc. The PinCard close calls `onActivate(id)`, which **toggles** (`persistent-map.tsx:87-88`), so a double fire would reopen the card.
   - Expected: one Esc closes the card and clears `?place=`.
   - Owning task: Task 1. It closes through a single guarded `close()`, and the step adds the manual check.
2. **Touch hit areas stealing taps from neighbours.** Cases: note/edit/remove cluster on a place row, checklist rows, Navigate just above the next place row.
   - Expected: tapping the visible control or its immediate surround hits that control, and never the next item's.
   - Owning task: Task 4. It changes gaps and row heights, and the 390×844 check includes taps between items.
3. **Error boundaries showing Next's production redaction text** ("An error occurred in the Server Components render…") as body copy.
   - Expected: fixed human copy plus the digest as a reference.
   - Owning task: Task 6. It drops `error.message` from both boundaries.
4. **Screen-reader summary going stale on day switch** (mobile day switcher, TP-0076).
   - Expected: the description always reflects the shown day. It is derived from `dayLabel` + `pins` props on every render.
   - Owning task: Task 5 unit tests plus the browser check.
5. **List/Map toggle state after leaving and re-entering the itinerary.** The existing unmount effect resets to List.
   - Expected: `aria-pressed` matches the visible state every time.
   - Owning task: Task 2 browser check.
