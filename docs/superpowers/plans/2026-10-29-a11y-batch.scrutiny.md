## Intent

Close the remaining small §5 findings, each as a local edit: honest popup semantics with Esc, a real toggle instead of a fake tablist, a search focus ring, ≥44 px touch areas, a spoken map summary, and human error copy.

### Simpler alternatives considered

- **Split the batch.** Eight tasks touch about 25 files across the map, itinerary and error surfaces, so a single PR rebases against five other plans. Splitting is tempting, but each task is small and has its own commit. **Kept as one plan.** The ordering notes below carry the coordination instead.
- **Real padding instead of `::after`.** Padding changes layout, which is what the coarse-only `::after` avoids. `::after` is the right tool. The risks are overlap and `touch-action`, handled in findings 3–4.
- **`unstable_rethrow` from `next/navigation`** instead of a hand-written `isNavigationError`. It's exported in Next 16.2, but it's marked unstable and it would change every catch shape. **Rejected.** The helper is fine once its digest list is right (finding 5).

### 3. Major: Navigate's 44 px box would spill into the neighbouring place rows. *Applied.*

- **Finding:** the plan named the risk (Review Focus 2) but no task handled it.
- **Evidence:** `.segment` is `padding: 6px 0` plus a chip with `padding: 4px 10px` and an 11 px font (`itinerary-list.module.css:7-16,86-97`), so the row is about 38 px. A 44 px `::after` centred on the ~17 px link extends about 13.5 px each way, which crosses the row edge by about 3 px. The `::after` is positioned and the place row above is earlier in the DOM, so the expanded area paints over it and steals its taps.
- **Change:** `@media (pointer: coarse) { .segment { min-height: 44px } }`, plus a tap check above and below Navigate. Once `itinerary-rows` Task 5 lands, the segmented control makes the chip ≥ 36 px and the row ≥ 48 px, so this rule is a no-op for editors and still needed for viewers.

### 4. Major: `tp-hit` on the reorder handle makes things worse on touch. *Applied (row removed).*

- **Evidence:** `.handle` is `opacity: 0` on touch, because the reveal rules are hover-only or focus-within (`sortable-place-list.module.css:15,28-38`), and it has `touch-action: none` (`:17`). `touch-action` isn't inherited by `::after`, so a drag started in the 8 px ring would be claimed by scrolling and cancel dnd-kit's `PointerSensor` (`sortable-place-list.tsx:144-145`). Inside the 28 px core, the invisible no-scroll zone stays as it is today.
- **Change:** the handle row is removed from the table. The reason is recorded under "Not changed". The fix belongs with the handle's touch discoverability work.

### 5. Major: `isNavigationError` would miss Next 16's `notFound()` digest. *Applied.*

- **Evidence:** Next 16.2.4 throws `NEXT_HTTP_ERROR_FALLBACK;404` (`http-access-fallback.js:41`). The repo's six inline checks test only `NEXT_REDIRECT*` and `=== 'NEXT_NOT_FOUND'` (for example `sortable-place-list.tsx:184`). That's a latent bug: an action calling `notFound()` shows an error toast instead of navigating. The plan copied it into the new helper.
- **Change:** the helper also matches the `NEXT_HTTP_ERROR_FALLBACK;` prefix, with a test.

### 6. Major: A18 in the place search left the inline error raw. *Applied.*

`place-search-picker.tsx:101-102` also does `setError(msg || 'Failed to add place')`, which renders `err.message` inline next to the toast. The row now replaces it with fixed copy.

### 7. Nit: line refs. *Applied where touched.*

The Google chip starts at `:213`, not `:214`. The place-search catch is `:100-103`. Other refs (`pin-card.tsx:17-20,30-36`, `map-preview-marker.tsx:45`, `sortable-place-item.tsx:128/171/190/198/238/241/273/285/300/307`, `segment.tsx:73,120`, `trip-delete-button.tsx:39`, `notes-view.tsx:221-268`, `ui/button.tsx:27-31`) are correct.

### 8. Nit: Esc on the Google InfoWindow. *Left as planned.*

React 19 attaches listeners to portal containers, and vis.gl renders InfoWindow content through a portal. So `stopPropagation` in the card's `onKeyDown` stops the native event at the content node, before any Google listener on an ancestor. A capture-phase Google listener would still fire. The plan's manual Esc check (Review Focus 1) is the right guard, and nothing more is needed.
